### 1.3 UX проблемы (формулировка без “советов”)
- Проблема P1: Входной путь “что это / что делать” не замкнут в UI (наблюдение).
- Проблема P2: STOP может быть воспринят как “ошибка” или “предупреждение”, а не terminal lock (наблюдение).
- Проблема P3: Метрики визуально похожи на “скоринг/оценку”, если нет нейтрального описания “что это” (наблюдение).
- Проблема P4: Locked features спамят и перехватывают основной поток (наблюдение).
- Проблема P5: Import не показывает provenance/режим достаточно явно (наблюдение).

## 2) Decisions (решения, строго в рамках ограничений)

D1. “Start Here” — компактный self-explaining блок, который:
- определяет: что инструмент делает (диагностика), чего НЕ делает (нет рекомендаций/оптимизаций),
- объясняет: где результат (Ledger),
- объясняет: что такое STOP как терминальный факт состояния с блокировкой сессии до reset.

D2. STOP визуализация — усиление “terminal” через:
- единый баннер/плашку “STOP (terminal)”,
- фактическое перечисление: что именно заблокировано,
- фактическая причина (если уже вычисляется/доступна в результате симуляции),
- без добавления новой семантики (только отображение/копирайтинг).

D3. Метрики — показывать только как факты:
- имя, значение, краткое нейтральное определение (“что измеряет”),
- запрет формулировок вида “хорошо/плохо/улучшить”.

D4. Gating — “группировка”:
- один компактный “Locked” список/панель,
- без всплывающих модалок, которые повторно прерывают основной поток,
- модалка допускается только по прямому клику пользователя на locked элемент.

D5. Import — provenance:
- показывать: источник данных (fixture/sample/LeanIX), timestamp (если есть), режим Demo/Tool (если уже есть), и факт “read-only”.

## 4) Manual test script (DoD: 90 секунд)

T0. Preconditions:
- чистый запуск `npm --prefix apps/cockpit run dev` (или сборка через build), никаких внешних источников не требуется.

T1. Open tool:
- Открыть Cockpit.
- Убедиться: виден “Start Here / Что это” и “Ledger — результаты”.

T2. Import sample/fixture:
- Выбрать fixture/sample import (реально существующий).
- Убедиться: provenance виден (источник + read-only).

T3. See model:
- Граф отображается.
- Никаких модалок locked не перехватывают поток без клика.

T4. Run one simulation:
- Запустить доступную симуляцию (существующую).
- Убедиться: ledger пополнился событиями.

T5. See STOP:
- Если STOP наступил: виден STOP (terminal) баннер, сессия заблокирована до reset.
- Если STOP не наступил: зафиксировать, как увидеть STOP на fixture (только факт: какая кнопка/сценарий уже есть).

T6. Reset:
- Выполнить существующий reset (если есть).
- Убедиться: разблокировка произошла (без изменения семантики).

## 5) Non-goals (жёсткие границы)
- Нет рекомендаций “что делать”, нет “улучшить X”.
- Нет скоринга/health-summary.
- Нет новых what-if поверхностей (кроме уже существующих).
- Нет экспорта/репортов за пределами существующих заглушек.
- Нет write-back в источники.
