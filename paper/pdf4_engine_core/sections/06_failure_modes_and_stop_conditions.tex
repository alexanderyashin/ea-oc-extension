\section{Failure Modes and STOP Conditions}
\label{sec:stop}

This section defines \textbf{terminal STOP} as a structural and irreversible
boundary of diagnostic admissibility.
STOP is \textbf{not} an error, \textbf{not} a warning, and \textbf{not} a
recommendation.
It denotes the condition under which further diagnostic evaluation is
formally non-admissible.

\subsection{Structural failures}

A \emph{structural failure} occurs when required preconditions for diagnostic
evaluation are violated in a manner that invalidates admissibility itself.

Examples include:
\begin{itemize}
  \item internal inconsistency of the invariant set $\mathcal{I}$;
  \item contradictions between declared invariants and threshold objects $\Theta$;
  \item violation of kernel invariants
        (see \texttt{I\_nonintervention}, \texttt{I\_nonadaptive}).
\end{itemize}

Structural failures are properties of the declared input configuration.
They \textbf{trigger} terminal STOP immediately.
They \textbf{do not} represent execution faults, runtime errors,
or implementation failures.

\subsection{Observability loss}

Observability loss occurs when the state snapshot $S$ lacks sufficient declared
information to evaluate required invariants and this insufficiency is
explicitly encoded in the observability descriptor $\mathcal{O}$.

\paragraph{No implicit completion.}
The kernel must not compensate observability loss by assumptions,
defaults, heuristics, estimation, or probabilistic inference.
This is a direct consequence of non-adaptivity and the prohibition of
learning/inference semantics (see \texttt{I\_nonadaptive}, \texttt{P\_learning}).

If required observability is missing, diagnostic admissibility is violated and
terminal STOP applies. This condition is \emph{distinct} from provenance loss:
observability concerns the declared completeness of $S$ at evaluation time.

\subsection{Threshold violations}

Threshold violations occur when invariant predicates that reference declared
threshold objects $\Theta$ evaluate to false.

\paragraph{Hard boundary semantics.}
Thresholds are treated as hard structural boundaries.
There is no notion of soft constraints, grace margins, tolerances,
or gradual degradation inside the kernel
(see \texttt{P\_optimization}).
Any violation constitutes loss of admissibility and
triggers terminal STOP.

\subsection{STOP region semantics}

STOP defines a terminal admissibility region in the diagnostic domain:
\[
\mathrm{STOP} = 1 \;\Rightarrow\; \nexists\, R' \text{ such that } R \prec R'
\]

That is, no admissible diagnostic result exists that can succeed $R$
for the same declared case.

\paragraph{Irreversibility.}
Irreversibility is structural, not temporal.
STOP does not denote a moment in time, a process stage,
or an execution phase.
It denotes the absence of any admissible continuation within the
kernel’s domain
(see \texttt{I\_stop\_mono}).

\paragraph{Monotonicity.}
Once STOP holds for a declared case, it remains true for that case.
STOP cannot be downgraded, overridden, weakened, or reinterpreted
without changing the declared inputs
(see \texttt{I\_stop\_mono}).

\paragraph{Singularity.}
STOP is singular and absolute per case.
There is no notion of partial, layered, probabilistic,
conditional, or recoverable STOP
(see \texttt{I\_binary}).

\subsection{Diagnostic operation graph (normative)}

The Engine Core admits a single, strictly directed diagnostic operation graph.
The graph is \textbf{acyclic}, \textbf{read-only}, and \textbf{terminal}.
This graph is normative and closed.

\paragraph{Nodes.}
The diagnostic graph consists of the following abstract operation nodes:
\begin{itemize}
  \item \texttt{InputDeclaration}: reception of $(S,\mathcal{I},\Theta)$;
  \item \texttt{StructuralValidation}:
        validation of kernel invariants and input consistency;
  \item \texttt{InvariantEvaluation}:
        evaluation of declared invariants;
  \item \texttt{STOP}:
        terminal non-admissibility state;
  \item \texttt{ResultEmission}:
        emission of $R$ with $\mathrm{STOP}=0$.
\end{itemize}

\paragraph{Edges (allowed).}
The only admissible directed edges are:
\[
\texttt{InputDeclaration}
\rightarrow
\texttt{StructuralValidation}
\rightarrow
\texttt{InvariantEvaluation}
\rightarrow
\{\texttt{STOP},\ \texttt{ResultEmission}\}
\]

\paragraph{STOP as terminal sink.}
\texttt{STOP} is a terminal sink node.
There exists no outgoing edge from \texttt{STOP}
(see \texttt{I\_stop\_mono}).

\paragraph{Forbidden edges.}
The following edges are explicitly forbidden:
\begin{itemize}
  \item any edge leaving \texttt{STOP};
  \item any feedback, backward, or cyclic edge between any nodes
        (see \texttt{P\_feedback}, \texttt{I\_nonadaptive});
  \item any retry, recovery, continuation, or re-evaluation edge;
  \item any edge conditioned on optimization, preference,
        ranking, or goal criteria
        (see \texttt{P\_optimization}, \texttt{P\_policy});
  \item any edge introducing control, steering,
        learning, or adaptive behavior
        (see \texttt{P\_control}, \texttt{P\_learning}).
\end{itemize}

Any artefact implying a diagnostic graph outside this definition is
non-admissible under OPS-1.

\subsection{Micro-instantiation (formal traces)}

The following minimal traces illustrate how violations of OPS-1 constraints
necessarily trigger terminal STOP. They are semantic counterexamples, not
implementation examples.

\paragraph{Trace A: Determinism violation.}
Given identical declared inputs $(S,\mathcal{I},\Theta)$, assume evaluation
produces two distinct results $R \neq R'$.
This violates determinism (\texttt{I\_det}) and immediately triggers
auto-disqualification (\texttt{D\_nondet}), hence STOP.

\paragraph{Trace B: Provenance loss.}
Assume an evaluation result lacks a complete append-only provenance record.
This violates provenance preservation (\texttt{I\_prov}) and triggers
auto-disqualification (\texttt{D\_prov\_loss}), hence STOP.

\paragraph{Trace C: Forbidden extension.}
Assume an extension introduces behavior dependent on past evaluations.
This introduces feedback or adaptation (\texttt{P\_feedback},
\texttt{P\_learning}), violating non-adaptivity (\texttt{I\_nonadaptive}) and
triggering auto-disqualification (\texttt{D\_adaptive\_ext}), hence STOP.

\subsection{Minimal audit trail for STOP}

When terminal STOP is triggered, the kernel records a minimal audit trail
in the append-only provenance record $P$:
\begin{itemize}
  \item identifier of the input snapshot $h(S)$;
  \item identifier of the invariant set $h(\mathcal{I})$;
  \item identifier of the threshold objects $h(\Theta)$;
  \item the structural classification label $\mathbf{c}$;
  \item the STOP flag.
\end{itemize}

This audit trail exists solely to support traceability and
conformance checks.
It must not be extended to provide causal narratives,
remediation advice, recovery logic, decision guidance,
or policy justification.
