\section{Scope and Non-Claims}

\subsection{Diagnostic-only boundary}

This artefact defines the \emph{Engine Core} as a \textbf{diagnostic-only kernel}.
Its scope is fixed, closed, and exhaustively limited to:
(i) accepting a declared structural state snapshot,
(ii) evaluating that snapshot against a declared invariant set,
(iii) emitting a structural classification, and
(iv) irreversibly terminating evaluation when terminal STOP conditions apply.

The Engine Core has \textbf{no causal influence} on the diagnosed system.
It \textbf{is not} an actuator, controller, optimizer, governance mechanism,
decision authority, or intervention layer.
Any embedding, exposure, or interpretation as such is \textbf{invalid}.

\paragraph{Closed operation set (invariant).}
The following operations exhaust the admissible behavior of the kernel:
\begin{itemize}
  \item \textbf{OBSERVE:} accept a read-only state snapshot;
  \item \textbf{EVALUATE:} evaluate declared invariants on that snapshot;
  \item \textbf{CLASSIFY:} map invariant satisfaction to a finite structural label;
  \item \textbf{STOP/HALT:} irreversibly terminate evaluation for the given case.
\end{itemize}

These operations denote \emph{structural roles}, not procedural steps.
No additional operations, phases, execution controls, or behavioral constructs
exist within the kernel.
Any extension beyond this set is \textbf{non-admissible}.

\subsection{OPS-1 contract vs.\ toolkits (OPS-2)}

OPS-1 is an \textbf{architecture-and-contract layer}.
It defines admissibility, invariants, prohibitions, authority, determinism,
reproducibility, and provenance identity.
OPS-1 \textbf{does not} define usage, tooling, workflows, interfaces, or decisions.

Any toolkit surface (CLI/GUI/scripts/integrations) belongs to OPS-2 and is, by
definition, an \textbf{exchangeable consumer} of the OPS-1 contract.
OPS-2 \textbf{may} change independently; OPS-1 \textbf{must not} be defined,
reinterpreted, or operationalized by OPS-2.
Any dependency in the opposite direction is \textbf{invalid}.

\paragraph{Binary compliance (invariant).}
OPS-1 compliance is \textbf{binary}: \emph{conformant} or \emph{non-ESTRA}.
Intent, usability goals, or product considerations are \textbf{irrelevant}.
Any toolkit that introduces prohibited semantics is \textbf{non-conformant}.

\paragraph{Non-normativity of toolkits (prohibition).}
Toolkits are \textbf{never normative}.
They \textbf{must not} introduce new semantic degrees of freedom,
reinterpret terminal STOP, weaken invariants, or transform structural labels
into prescriptions.
UX, adoption, or product arguments \textbf{do not justify} any semantic change
to OPS-1.

\paragraph{Auto-disqualification (boundary violation).}
Any representation of OPS-1 as a ``method'', ``tool'', ``framework'',
``best practice'', ``playbook'', or ``how-to'' is a category error.
Any consumer layer that induces or implies ``you should do X'' from OPS-1 output
or from terminal STOP is \textbf{non-conformant} and therefore
\textbf{non-ESTRA}.

\subsection{No-prescription / no-management claims}

This document contains \textbf{no prescriptive} and \textbf{no managerial}
statements.

\paragraph{Explicit non-claims (prohibition).}
The Engine Core does \textbf{not}:
\begin{itemize}
  \item recommend actions, remediations, or interventions;
  \item define roadmaps, sequences, or execution plans;
  \item set targets, KPIs, objectives, or success criteria;
  \item prioritize options, rank alternatives, or compare desirability;
  \item allocate resources or define governance or control processes;
  \item provide best practices, frameworks, methodologies, or transformation guidance.
\end{itemize}

Any process, facilitation, governance, or decision-making that consumes diagnostic
output is \textbf{external} to the Engine Core and outside OPS-1 authority.

\subsection{What the engine does not infer}

The Engine Core \textbf{does not} infer missing structure or enrich semantics.
It operates exclusively on explicitly declared inputs.

\paragraph{Forbidden inference classes (prohibition).}
The kernel does \textbf{not}:
\begin{itemize}
  \item infer intent, priorities, accountability, or organizational motives;
  \item infer causal narratives beyond declared invariant reference;
  \item forecast future states or simulate counterfactual scenarios;
  \item learn from history or adapt thresholds, invariants, or rules;
  \item complete missing observability via assumptions, heuristics, or estimation.
\end{itemize}

\paragraph{Structural determinacy (descriptive).}
The only determinacy claim is internal and structural:
for identical declared inputs (state snapshot, invariant set, thresholds),
the kernel yields the same classification and terminal STOP decision.
This statement applies \textbf{only} to kernel behavior and makes
\textbf{no claim} about determinism of the world, organizations, or outcomes.

\paragraph{STOP as boundary, not signal (invariant).}
Terminal STOP is \textbf{not} advice, \textbf{not} an error,
and \textbf{not} a recoverable warning.
It denotes a structural boundary beyond which further diagnostic evaluation is
formally non-admissible for the given case (see Section~\ref{sec:stop}).
