\section{Input Admissibility}

\subsection{Normative Requirement}
An input is \textbf{admissible} under OPS-0 if and only if it satisfies all declared input constraints
defined by this contract and is classifiable by reference to the appendix registries (CT-xx tables).

RUN-OPS0-01 \textbf{MUST NOT} define concrete admissibility criteria, formats, or schemas.
Input admissibility in this run is therefore \textbf{declarative only}.

\subsection{Missingness and Ambiguity}
If required input properties are missing, incomplete, or ambiguous, the input \textbf{MUST}
be classified as \emph{partially admissible} or \emph{non-admissible} with an explicit
\texttt{epistemic\_status} indicating the nature of the deficiency.

If ambiguity prevents classification, the input \textbf{MUST} result in \textbf{STOP / NO-GO}
without further processing.

\subsection{Binding to Registries}
Input admissibility classes and ambiguity categories are normatively bound to appendix registries (CT-xx tables).
In RUN-OPS0-01, these registries are referenced for completeness but \textbf{MUST NOT} be populated or executed.
