\section{Input Admissibility}

\subsection{Normative Requirement}
An input is classified as \textbf{admissible} under OPS-0 if and only if it satisfies
all applicable \textbf{contract-level constraints} defined in this document
and is classifiable by reference to the appendix contract registries (CT-xx tables).

RUN-OPS0-01 \textbf{MUST NOT} define, infer, or operationalize any concrete admissibility criteria,
formats, schemas, thresholds, or validation mechanisms.
Input admissibility in this run is therefore \textbf{strictly declarative} and
limited to classification outcomes only.

No implicit assumptions, defaults, heuristics, or best-effort interpretations
of inputs are permitted.

\subsection{Closed-world assumption}
OPS-0 applies a \textbf{closed-world assumption} to input admissibility.

Any input property, structure, or condition
that is not \textbf{explicitly declared} and
\textbf{explicitly classifiable} within the contract surface
and by reference to the appendix registries
\textbf{MUST} be treated as \textbf{non-admissible}.

Absence of classification authority
\emph{constitutes non-admissibility}.
No deferral, provisional acceptance,
or implicit admissibility is permitted.

\subsection{Missingness, Ambiguity, and Classification Limits}
If required input properties are missing, incomplete, inconsistent, or ambiguous,
the tool \textbf{MUST} attempt classification only at the level permitted by the contract.

The resulting classification \textbf{MUST} be explicitly reflected via
\texttt{epistemic\_status} and \textbf{MUST NOT} enable continuation, imputation,
fallback, or compensatory logic.

If ambiguity, incompleteness, or inconsistency prevents unambiguous classification
within the declared contract surface,
the tool \textbf{MUST} emit a terminal \textbf{STOP} or \textbf{NO-GO} outcome
and terminate the run without further processing.

No intermediate, degraded, exploratory,
or speculative execution modes are permitted.

\subsection{Binding to Registries (Exclusive)}
All input admissibility classes, ambiguity categories, and classification outcomes
are \textbf{normatively bound} to appendix contract registries (CT-xx tables).

In RUN-OPS0-01:
\begin{itemize}
  \item registries are referenced for structural completeness only;
  \item registries \textbf{MUST NOT} be populated, executed, or interpreted;
  \item no admissibility class may be inferred
        outside explicit registry bindings
        or explicit contract constraints.
\end{itemize}

Any input that cannot be
\textbf{explicitly classified as admissible}
by registry binding and contract reference
\textbf{MUST} be treated as \textbf{non-admissible}
under OPS-0 in this run.
