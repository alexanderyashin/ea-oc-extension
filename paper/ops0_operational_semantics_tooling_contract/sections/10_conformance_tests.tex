\section{Conformance Tests (Normative Classification Matrix)}
\label{sec:ops0_conformance_tests}

\subsection{Scope and intent (Binding)}
This section defines a \textbf{normative conformance classification matrix}
for OPS-0 outputs and runs.

The matrix specifies \emph{contract-level classification requirements only}.
It \textbf{DOES NOT} define and \textbf{MUST NOT} be interpreted as:
\begin{itemize}
  \item executable test code or test procedures,
  \item an implementation guide or reference architecture,
  \item a benchmark, metric system, or scoring framework,
  \item a quality assurance, validation, or verification process,
  \item an example, illustration, or case study.
\end{itemize}

The term ``test'' is used \textbf{exclusively} in the
\emph{contractual sense of classification predicates}.
It denotes required outcomes under stated conditions,
not executable evaluations or procedural checks.

Any engine, toolkit, process, or artefact
claiming OPS-0 conformance
\textbf{MUST} satisfy all classifications
defined in this section
\emph{exactly as stated}.
No alternative interpretation,
procedural substitution,
weakening, approximation,
or partial satisfaction
is permitted.

\subsection{Failure classifications (Canonical)}
Each conformance classification yields
\textbf{exactly one}
of the following
\textbf{contract-level outcomes}:

\begin{itemize}
  \item \textbf{STOP} —
        terminal epistemic classification;
        the output is invalid and the run
        \textbf{MUST} terminate immediately.
  \item \textbf{NO-GO} —
        contractually forbidden emission
        or tool-visible behavior;
        the output \textbf{MUST NOT} be produced.
  \item \textbf{NON-CONFORMANT} —
        required contract surface is missing,
        incomplete, inconsistent, or violated;
        the output is rejected.
\end{itemize}

These classifications are
\textbf{mutually exclusive}
and carry \textbf{no}
remediation, recovery,
downgrade, continuation,
compensatory, or corrective semantics.

\subsection{Evaluation precedence (Binding)}
Conformance classification under OPS-0
\textbf{MUST} respect the following
strict precedence order:

\begin{enumerate}
  \item \textbf{STOP} conditions are evaluated first.
  \item \textbf{NO-GO} conditions are evaluated second.
  \item \textbf{NON-CONFORMANT} conditions are evaluated last.
\end{enumerate}

If any STOP condition applies,
the process \textbf{MUST} emit STOP immediately
and \textbf{MUST NOT} perform, complete,
or rely on any further classification,
phase determination,
derivation, or output emission.

No partial execution,
partial evaluation,
intermediate result generation,
or deferred classification
is permitted prior to or after STOP.

\subsection{Conformance gate (Hard)}
A process, toolkit, or output
claiming OPS-0 conformance
\textbf{MUST} satisfy all classifications
T-OPS0-01 through T-OPS0-10.

Any single failure:
\begin{itemize}
  \item \textbf{MUST} result in rejection
        of the output as OPS-0 non-conformant;
  \item \textbf{MUST NOT} be compensated,
        deferred, downgraded, bypassed,
        or contextually excused;
  \item \textbf{MUST NOT} be concealed
        by partial results,
        explanatory text,
        or auxiliary artefacts.
\end{itemize}
